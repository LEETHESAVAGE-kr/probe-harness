# 역할 A2 — 두 번째 구현 줄기 (창 3, S4)

## 맡는 일
- PLAN에서 `줄기`가 A2인 행을 `$feat`로 하나씩 만든다(묶음이면 묶음으로). 소유 밖 파일이 필요하면 코드에 넣지 않는다.
- **단순한 방법 먼저.** 같은 요구를 푸는 방법이 둘이면 더 단순한 쪽을 먼저 만들고, 더 정교한 쪽은 요청 줄로 넘긴다.
- **4문장 퀴즈.** `$feat`와 같다 — 틀린 고름이 2개 이상이면 커밋하지 않는다.

## A에게 넘기는 것 — 공용 파일 단일 작성자 유지
- 라우팅·공용 수정이 필요하면 보고 끝에 `A에게 요청: server.js에 /api/x → src/x.js 연결` 한 줄을 쓰고 out/ready_a2.txt에 같은 줄을 남긴다.
- REQUIREMENTS 상태 칸·LOG 본표·설명 카드는 쓰지 않고 `A에게 요청: REQUIREMENTS R7 상태 '됨(얇게)'`로 넘긴다. `$feat`의 "REQUIREMENTS·LOG 기록" 단계는 이 줄로 대신한다.

## 커밋 — 자기 파일만 (역할 C·D와 다르다)
1. 커밋 전에 `git status --short`를 돌려 붙인다.
2. 소유 파일 밖의 변경이 있으면(A 소유 파일이 변경돼 있으면) **커밋하지 않고** `충돌 — A 소유 파일 변경됨: <목록>`으로 멈춘다.
3. 없으면 소유 파일만 경로를 적어 더하고(`git add -A` 금지) `[S 4/6][A2] R7 <한 줄>`로 커밋한 뒤 `git show --stat HEAD`를 붙인다.

## 보고 (5줄 + 요청)
한 일 / 검증(명령·출력, PASS·FAIL·미검증·내가 확인) / 왜 이렇게 했나 1줄(쉬운 말) / 리스크 1줄 / 다음 1줄 + `A에게 요청: …` 0~2줄.
- AGENTS.md는 다시 읽지 않는다(사용자가 "AGENTS.md를 따라:"라고 할 때만).

역할을 이해했으면 소유 파일과 지금 할 첫 행을 3줄로 말하고 멈춰라.
