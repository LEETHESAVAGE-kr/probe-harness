# $screen — 역할별 화면 확인 (S3 끝 · S5)

## 할 일
1. 서버는 사용자가 띄워 두었다(켜거나 끄지 않는다). README_RUN·HOW_TO_RUN에서 포트를 찾는다.
2. `node /tmp/harness/scripts/screen_check.mjs --port <포트>` 를 실행하고 출력 전체를 붙인다. 데모 계정이 HOW_TO_RUN 표에 없으면 사용자에게 아이디·비밀번호를 물어 `--user … --pass …`로 다시 돌린다. 특정 경로만 볼 때는 `--path /경로`.
3. 출력 첫 줄 "방식"을 읽는다.
   - **playwright**: 표의 판정(보임 / 빈 화면 / 로그인 실패)을 그대로 보고하고, 빈 화면·로그인 실패 행마다 스크린샷 경로와 "보인 글 일부"를 한 줄씩 보여 준다.
   - **폴백**: 판정이 "미측정"인 것은 실패가 아니다. 표 아래 "사람이 Browser로 확인할 것" 목록을 그대로 보여 준다. 사용자가 본 것을 알려 주면 그 행의 판정만 "내가 확인"으로 고친다(사용자가 말하지 않은 행은 고치지 않는다). 폴백에서도 HTTP로 확실한 빈 화면(글 20자 미만·스크립트 없음)은 "빈 화면"으로 나온다.
4. 빈 화면이 있으면 고치지 말고 `$debug`로 넘길 증상 한 줄(역할·경로·보인 글)을 써 준다.
5. 역할 카드 D(데이터·측정 탭)로 일하는 세션이면 커밋하지 말고 "커밋 준비됨: out/screen_check.md out/screens/"로 끝낸다. 혼자면 `[S n/6] 화면 확인 보임 n·빈 화면 n·미측정 n` 으로 그 둘만 커밋한다.

## 하지 않는 것
playwright 설치 / 판정을 꾸며 내기(본 적 없는 행을 "보임"·"내가 확인"으로) / 코드 수정 / 서버 재시작.

## 끝 조건
out/screen_check.md가 있고, 행마다 판정(보임·빈 화면·로그인 실패·미측정·내가 확인) 중 하나가 적혀 있다.

## 보고 (5줄)
한 일 / 검증: 보임 n·빈 화면 n·로그인 실패 n·미측정 n / 왜 이렇게 판정했나 1줄 / 리스크: 아직 아무도 안 본 화면 / 다음: 빈 화면이면 `$debug`, 폴백이면 체크 목록을 Browser로.
