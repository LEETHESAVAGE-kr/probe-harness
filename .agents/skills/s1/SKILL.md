고치는 파일: REQUIREMENTS.md · README가 백틱으로 적은 필수 파일 중 없는 것(껍데기) · out/inventory.md · (장문 모드일 때만) out/examples.md · LOG.md 본표 S1 한 행. README.md와 제공 데이터는 읽기만 한다.

> 사용자가 명령 뒤에 붙인 문장(줄글이어도 된다 — 그 안의 목적·근거·범위·하지 마라·내 판단·확인)은 이 파일의 지시보다 우선한다(고치는 파일 범위와 "멈춰라"는 그대로). 보고 첫 줄에 "이번 목적: …"을 붙인 문장에서 한 줄로 옮기고, 붙인 문장이 없으면 리스크 칸에 "[목적 줄 없음]"이라고 적는다.

# $s1 — 요구 전수표와 필수 파일 껍데기 (S1, 8~30분)

## 할 일 (순서대로, 각 단계 출력을 붙인다)
1. `node /tmp/harness/scripts/readme_to_requirements.mjs` 를 실행하고 명령과 출력을 그대로 붙인다. 하네스가 `./.harness`에 있으면 그 경로로 실행한다.
   - 출력 첫 줄의 "요구 n · 규칙 n · 산출물 n"을 REQUIREMENTS.md 표 행 수와 대조해 한 줄로 말한다.
   - "경고:" 줄은 그대로 다시 보여 준다. "번호 목록 요구가 0개" 경고면, README 문단마다 요구를 원문 그대로 REQUIREMENTS에 행으로 옮기고 종류 칸에 '요구(번호 없음)'로 표시한 뒤 진행한다. 묻지 않는다.
   - "기존 REQUIREMENTS.md는 덮어쓰지 않았다" 경고면 out/REQUIREMENTS.new.md에만 있는 행을 목록으로 보여 준다. 옮기지는 않는다.
2. README·data/README.md·*_SCHEMA.md에서 표로 뽑히지 않은 해석 제약 문장(예: "~는 실적에서 빠진다", "~는 포함하지 않는다")이 보이면 원문 그대로 REQUIREMENTS 표 끝에 '규칙' 행으로 추가하고 출처 `— 파일:줄`을 단다. 해석하거나 줄이지 않는다.
3. 출력의 "뼈대 추천" 줄과 "명령:" 줄을 그대로 보여 주고, 부품마다 근거 줄(README.md:n)을 README에서 열어 맞는지 한 줄로 말한다. 깔지는 않는다 — 무엇을 깔지는 사용자가 PLAN에서 정한다.
4. 생성된 껍데기 파일 목록을 보여 준다. 껍데기에 README 양식 본문이 들어간 것(질문형 문서)은 따로 표시한다. 껍데기의 내용은 채우지 않는다.
5. 데이터 파일(CSV·TSV·JSON)을 전부 찾아, 파일마다 머리줄을 보고 대상 하나하나를 가리키는 ID 열(줄마다 다르고 여러 파일에 함께 있는 열)을 골라 고른 열과 이유를 한 줄로 말한다.
6. `node /tmp/harness/scripts/inventory.mjs <데이터 파일 전부> --by <그 열> --out out/inventory.md` 를 실행하고 명령과 출력을 붙인다. CSV가 하나도 없으면 `node /tmp/harness/scripts/inventory.mjs --out out/inventory.md`(인자 없이 — data/의 JSON·TXT·MD를 파일마다 한 행으로 센다). 데이터가 없으면 "데이터 없음"이라고 쓰고 건너뛴다.
7. LOG.md 본표에 S1 한 행(내가 지시한 것 `$s1` / AI가 한 것 / 내가 직접 확인한 것은 비워 둔다 / 시각은 `date`)을 쓴다.
8. `[S 1/6] 요구 n·규칙 n·산출물 n, 껍데기 n` 형식으로 커밋하고 `git show --stat HEAD`를 붙인다. 역할 카드 B·C·D로 일하는 세션이면 커밋하지 말고 "커밋 준비됨: 파일 목록"으로 끝낸다.

## 장문 모드 — `wc -l README.md`가 2,000줄 이상이거나 범위 줄에 `장문`이 있을 때만 (아니면 이 절을 통째로 건너뛴다)
1단계 스크립트는 그대로 돌리고, 그 출력 위에서 네가 편집한다. 표 머리·행 번호(R·K·Q·F·X)·기존 열 이름은 바꾸지 않고 열 2개만 끼운다. 사용자가 적은 '고칠 파일' 줄이 좁아도 out/examples.md는 쓴다.
- REQUIREMENTS 표에 **`근거 절`** 열(그 행이 어느 제목 아래 문장인가)과 **`★`** 열을 `상태` 앞에 더한다(`상태`는 맨 끝 열로 둔다). ★은 '제출물·평가·반드시' 절에 직접 걸린 행만.
- 배경·사례·등장인물·목차 절에서 나온 행은 표에서 빼 표 아래 `## 후보(요구인지 담당자에게 확인)` 절로 내린다(번호·원문·출처 그대로, 지우지 않는다).
- out/examples.md에 README의 '예를 들어·예시·샘플·표·화면' 자리를 절 이름과 함께 전부 뽑고, 입력→출력 쌍으로 읽히는 것은 `| 절 | 입력 | 출력 |` 표로, 없으면 "예시 없음" 한 줄.
- 장문 모드의 보고는 맨 첫 줄이 `요구 n행(★ k) · 후보 m · 예시 쌍 p`(n은 후보로 내린 행을 뺀 표의 R 행 수)이고, "이번 목적: …"은 둘째 줄이다. 끝 조건의 행 수는 표 + 후보의 합으로 센다.

## 하지 않는 것
README.md 수정·생성 / '만들 것·안 만들 것' 칸 채우기(사람이 정한다) / 껍데기 내용 쓰기 / 해석·구현.

## 끝 조건
REQUIREMENTS.md(행 수 = 출력 첫 줄의 합계 + 2단계에서 더한 행)와 껍데기 파일과 out/inventory.md가 한 커밋에 들어 있다.
