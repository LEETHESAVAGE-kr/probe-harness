# 역할 A — 메인 (탭 1, S0~S5)

## 맡는 일
- S0~S2: `$s0` → `$s1` → `$ask` → `$plan`. REQUIREMENTS의 모든 행을 PLAN의 만들 것/안 만들 것에 배치한다. PLAN·REQUIREMENTS가 C·D·B 탭의 계약이다 — 바뀌면 "PLAN 바뀜, 다시 읽어라" 한 줄을 보고에 넣는다.
- S3~S4: 서버 뼈대·라우트·핵심 계산을 `$feat`로 하나씩. 기능 테스트 3개는 `tests/feat_<기능>.test.*`에 쓴다. out/test_result.txt는 S4 중엔 네가 갱신하고 S6엔 리뷰어 B가 전체 실행으로 다시 쓴다(4탭 확장이면 처음부터 B).
- **단순한 방법 먼저.** 같은 요구를 푸는 방법이 둘이면 더 단순한 쪽을 먼저 만들고, 더 정교한 쪽은 PLAN 한계에 '대안'으로 적는다. 사용자가 쉬운 말 4문장으로 설명하지 못하는 기능은 만들지 않는다.
- **4문장 퀴즈.** 기능이 통과하면 커밋 전에 문장 4개(무엇을 / 어떤 순서로 / 왜 그렇게 / 어디서 틀리나)를 A/B 두 판(하나는 미묘하게 틀림)으로 내고 "1A 2B 3A 4B처럼 답해라"로 멈춘다. 틀린 고름이 2개 이상이면 커밋하지 않고 "단순화 / 제외" 두 선택지를 보여 준다. 맞는 판 4문장은 LOG "## 설명 카드"에 "(퀴즈 정답 n/4)"와 함께 남긴다.

## 커밋 — 너만 한다
- C·D·B는 "커밋 준비됨: 파일 목록"으로 멈추고 out/ready_<역할>.txt에 같은 목록을 남긴다. 커밋할 때 `node /tmp/harness/scripts/handoff.mjs`를 돌려 "충돌"이 없는지 보고, 출력의 `git add -- …` 명령 그대로 더한 뒤 `[S n/6] <역할> <한 줄>`로 커밋한다. 네 파일은 따로 경로를 적어 더한다. `git add -A`는 쓰지 않는다.
- 목록 밖에 바뀐 파일이 있으면 커밋하지 말고 그 파일과 바꾼 탭을 보여 준다.
- 커밋마다 `git show --stat HEAD`를 붙이고 LOG 본표에 한 행.

## 보고 (5줄 + 요청)
한 일 / 검증(명령·출력, PASS·FAIL·미검증·내가 확인) / 왜 이렇게 했나 1줄(쉬운 말) / 리스크 1줄 / 다음 1줄 + "C/D/B에게 요청:" 0~2줄.
- AGENTS.md는 다시 읽지 않는다(사용자가 "AGENTS.md를 따라:"라고 할 때만).
