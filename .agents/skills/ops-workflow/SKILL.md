# ops-workflow — 운영 절차 (S1~S6)

## 0. 시작할 때 (파일이 없으면 만든다)
- 과제 폴더 **루트**에 `AGENTS.md`와 문서 8개(INTERVIEW·AGREEMENT·SOURCE_MATRIX·FINDINGS·REPORT·DECISIONS·VERIFY·HANDOFF)가 없으면 아래 '최소 머리'로 루트에 만들고 커밋한 뒤 목록만 보여주고 멈춘다(templates/ 폴더를 만들지 않는다). 있으면 AGENTS.md → AGREEMENT.md → HANDOFF.md 순으로 읽고 현재 단계를 5줄로 보고한다.
- 과제 README.md는 절대 덮어쓰지 않는다. 덮였으면 `git checkout -- README.md`로 되돌리고 알린다.
- 최소 머리: INTERVIEW `질문|답 원문|숫자|시각` / AGREEMENT `이해한 문제|성공 기준(목표 숫자)|가정·임시 기준|만들 것|안 만들 것|담당자 확인 시각` / SOURCE_MATRIX `항목|파일 값|포털 값|담당자 말|일치 여부(상태·날짜·숫자 칸마다)|근거 위치` / FINDINGS `무엇|어디서 어긋남|왜 중요|누구에게 확인|권고|확인한 숫자` / REPORT 맨 위 보고용 요약 3줄 + `결론 숫자|목표 대비|근거 파일|남은 확인` / DECISIONS `결정|대안|약점|검증` + 고정 절 'AI 위임 vs 직접 검증' `맡긴 것|내가 확인한 것|어떻게|확인한 숫자` / VERIFY `무엇을|어떻게(명령·독립 재계산·일부러 틀려 보기)|결과 숫자|파일` / HANDOFF `현재 단계|완료|미완|다음 3개`.

## 1순위 규칙 (모든 단계)
데이터를 빼거나 바꾸거나 합치면, **먼저** 이유와 전후 건수·합계 비교표를 `out/changes_log.md`에 한 행 쌓고 진행한다: `| 단계 | 처리(무엇을 왜) | 전 건수 | 후 건수 | 전 합계 | 후 합계 | 차이 | 결론을 바꾸나 |`. "더 확인해야 한다"로 끝내지 않는다.

## 규칙 6 (전·출·하·스·증·검)
전후(위) / 출처: 모든 숫자에 `파일:행`·`포털 메뉴`·`담당자 시각` / 하나: 지시 하나 = 범위 하나 + 출력 파일 하나, 고칠 곳만 고침, 전체 재작성 금지 / 스크립트: 파일은 직접 읽고 반복 확인은 check.py로 재실행, 스크립트는 out/에만 쓰고(uploads 원본·사람 문서 덮어쓰기 금지) 출력은 utf-8, 포털 값은 portal/ / 증거: "완료"엔 명령과 출력 숫자, 안 돌린 건 "미검증" / 검증: 전후 비교·출처 대조·독립 재계산·일부러 틀려 보기·최종 검토는 아끼지 않는다(아낄 건 낭비).

## 단계
| 단계 | 할 일 | 끝 조건(파일) | 커밋 |
|---|---|---|---|
| S1 확인 | uploads 파일별 열·행 수·기간·빈칸·중복 키(같은 대상·같은 날짜 포함)·표기 흔들림·메모 열 내용·기준표에 없는 ID 수를 센다(해석 금지). 포털 메뉴 구성을 사람에게서 듣고 적는다 | out/inventory.md | `[S 1/6]` |
| S2 인터뷰 | 담당자 질문 초안을 **3~4개씩 묶어 2~3번** 보낸다(① **최근 바뀐 기준? 파일·포털·자료함마다 다른 기준? 날짜 붙은 기준 문서가 지금도 맞나?** 뺄 데이터·상태값 뜻 ② 상황·현재 방식 ③ **목표 숫자**·결과물 형태). 한 번만 보내고 끝내지 않는다 — 목표 숫자 질문은 빼지 않는다. 답은 원문·시각 그대로 | INTERVIEW.md 숫자 칸 ≥3, 목표 값 | `[S 2/6]`(S3와 묶어도 됨) |
| S3 합의 | AGREEMENT 7칸. 근거 없는 칸은 "미확인". **S4 대조 전에** 사람이 담당자에게 "맞는지, 빠진 게 있는지" 확인받고 시각 기록 | AGREEMENT 확인 시각 | `[S 3/6]` + HANDOFF |
| S4 대조 | 포털 값은 portal/에(옮긴 방법 표기) → 화면 합계 대조(화면에 합계가 없으면 쪽마다 행 값을 더한 합, out/portal_check.py로 저장) → check.py로 키 대조(양쪽·파일만·포털만·값 다름) → SOURCE_MATRIX | out/source_compare.csv, out/changes_log.md | `[S 4/6]` |
| S5 정리 | 불일치 → FINDINGS(6칸, 확인한 숫자는 out/에서), REPORT(보고용 요약 3줄·결론 숫자·목표 대비·민감도), DECISIONS 재료(대안·약점)만 — 본문은 사람이 | FINDINGS.md, REPORT.md | `[S 5/6]` + HANDOFF |
| S6 검증·제출 | 새 터미널 탭 codex 리뷰어: verify.py(check.py를 import하지 않고 원본에서 결론 숫자 다시 세기, 담당자 확인 기준값은 따로 다시 적기) + 규칙 하나 일부러 깨서 잡히는지(먼저 걸리는 행 수를 센다 — 0행이면 사본에 반례 행) + 문서 숫자 ↔ out/ 대조 + 건수 보존 → VERIFY(사람 문서, 스크립트가 덮어쓰지 않음). 최종 HANDOFF | VERIFY.md | `[S 6/6]` |

## 전환 의식 (S3·S5·S6 끝, 또는 대화가 길어질 때)
1. HANDOFF 갱신(현재 단계·완료·미완·다음 3개·다시 돌릴 명령과 결과 한 줄). 2. check.py 재실행해 결과 한 줄 확인. 3. 커밋 본문 3줄: 드리프트 / 증거 / 의심. 4. `git show --stat HEAD`. 5. 사람이 새 터미널 탭에서 codex를 열면 이 skill부터.

## 사람이 손으로 한 일
"기록만 해라: …"(포털 옮기기·원본 눈 대조·담당자 확인)를 받으면 DECISIONS 고정 절 **'내가 확인한 것'** 칸과 VERIFY V-07에 한 줄만 남긴다. '맡긴 것' 칸에는 네가 만든 스크립트·초안·표를 적는다. 기록 지시에는 다른 작업을 하지 않는다.
포털 값은 옮긴 뒤 행 수·숫자 열 합계·화면 요약 숫자를 화면과 대조해 out/portal_check.md에 남긴다.

## 하지 않는 것
요청 안 한 분석·차트 / 출처 없는 숫자 / AGREEMENT 목표를 담당자 확인 없이 변경 / DECISIONS 본문 작성 / 실패를 숨기는 처리.
