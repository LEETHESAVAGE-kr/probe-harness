고치는 파일: 원인을 확인한 뒤의 그 파일 하나(확인 전에는 아무것도 고치지 않는다) · out/diag_web.txt. 그 밖의 파일은 읽기만 한다.

> 사용자가 명령 뒤에 붙인 목적·범위·하지 마라·내 판단·확인 줄은 이 파일의 지시보다 우선한다(고치는 파일 범위와 "멈춰라"는 그대로). 보고 첫 줄에 "이번 목적: …"을 그 문장 그대로 옮기고, 붙인 줄이 없으면 리스크 칸에 "[목적 줄 없음]"이라고 적는다.

# $debug — 원인 먼저, 고치기는 나중 (어느 단계든)

## 5규칙
1. **원인 확인 전 수정 금지.** 추측으로 코드를 바꾸지 않는다. 바꾸기 전에 "원인: … / 근거: 명령 출력 한 줄"을 적는다.
2. **재현 명령 먼저.** 증상을 다시 일으키는 명령 하나(curl·테스트 이름·`node …`)를 적고 돌려서, 실패 출력을 그대로 붙인다. 재현이 안 되면 그렇다고 말하고 멈춘다.
3. **최근 바뀐 파일부터.** `git diff --stat HEAD~3`과 `git log --oneline -5`를 붙이고, 증상과 이어질 만한 파일을 고른다.
4. **가설은 1개씩, 가설마다 확인 명령 1개.** `| # | 가설 | 확인 명령 | 결과 | 맞나 |` 표에 한 줄씩 쌓는다. 맞는 가설이 나오면 그 원인만 고치고 재현 명령을 다시 돌려 통과를 붙인다.
5. **같은 문제로 수정이 3번 실패하면 멈춘다.** 지금까지의 가설·결과 표와 "다음에 확인할 것" 한 줄을 보고하고 사용자 판단을 기다린다.

## 화면 문제(빈 화면·안 붙음·로딩만)면 이것부터
- `node /tmp/harness/scripts/diag_web.mjs <포트>`를 돌려 표 전체와 마지막 줄 "원인 후보"를 붙인다. 서버는 띄우거나 끄지 않는다.
- 멈춘 단계가 곧 첫 가설이다: ① 서버 꺼짐 → 사용자에게 서버 탭 재시작 요청 / ② 127.0.0.1 바인딩 → listen 주소 / ③ 첫 화면 404·빈 본문 → 정적 폴더·라우트 / ④ js·css 404·MIME → HTML의 경로 / ⑤ 401·403 → 로그인 뒤 다시.
- 서버 쪽이 다 PASS면 Browser의 포트·경로 입력과 새로고침, 브라우저 콘솔 오류 문구를 사용자에게 받아 4규칙으로.

## 하지 않는 것
원인 확인 전 수정 / 여러 가설을 한꺼번에 고치기 / 테스트 기대값을 바꿔 통과시키기 / 서버 프로세스 종료(사용자가 띄운 것) / 증상과 무관한 리팩터링.

## 끝 조건
재현 명령이 통과로 바뀐 출력이 붙어 있다. 또는 수정 3번 실패로 멈춰 가설 표를 보고했다.
