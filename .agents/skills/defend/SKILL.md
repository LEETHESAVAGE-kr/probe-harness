고치는 파일: LOG.md 끝 "## 설명 준비" 절 하나(없으면 만들고, 있으면 그 절만 다시 쓴다) · AI_COLLABORATION.md의 Q1~Q3 답 칸 · out/defend_cards.md · (초안을 고른 뒤) LOG.md 본표 한 행. 다른 파일과 LOG의 다른 절은 읽기만 한다.

> 사용자가 명령 뒤에 붙인 목적·범위·하지 마라·내 판단·확인 줄은 이 파일의 지시보다 우선한다(고치는 파일 범위와 "멈춰라"는 그대로). 보고 첫 줄에 "이번 목적: …"을 그 문장 그대로 옮기고, 붙인 줄이 없으면 리스크 칸에 "[목적 줄 없음]"이라고 적는다.

# $defend — 설명 준비 (S6, 163~172분)

## 근거로 읽을 것 (이것만)
PLAN · REQUIREMENTS · LOG(본표 · "설명 카드" · "AI 위임 vs 직접 검증" · 담당자 대화) · DECISIONS · VERIFY · HOW_TO_RUN · AI_COLLABORATION · tests/ · out/ · 코드. out/prove.md가 있으면 그 비교표(기준안·하한·우리 안)를 ③ 숫자와 ② 기준과 이유에 쓴다. 근거가 이 안에 없는 문장은 쓰지 않고 그 자리에 "기록 없음"이라고 쓴다.

## 쓸 것 — 빈 줄 빼고 60줄 이내, 장마다 제목 1줄 + 5줄 이하
1. **구조 한 장** — 요청이 들어와 응답이 나갈 때까지의 파일 순서(`server.js → … → 저장 → 응답`), 파일마다 하는 일 한 줄. DB(또는 파일 저장)와 설정(환경변수)을 어디서 읽는지 한 줄. 없는 단계(입력 검증·결과 검증·잠금)는 "없음 — 그래서 ○○".
2. **기준과 이유** — 판정·계산 기준이 무엇인지, 더 단순한 대안이 왜 부족했는지, 더 정교한 대안을 왜 안 했는지(PLAN 한계의 '대안'). 각각 근거 시각(담당자 답)이나 DECISIONS 번호.
3. **숫자** — 입력 = 사용 + 버림(사유별), 처리 전후 건수(out/changes_log.md), 테스트 n/n(out/test_result.txt), curl 상태(out/browser_check.txt), 10배 입력 시간(out/scale_check.txt), 동시 요청 결과(out/concurrency_check.txt), docker build 결과. 없는 파일은 "미측정".
4. **AI를 바로잡은 지점** — 설명 카드의 "내가 고치거나 거부한 제안"과 LOG 고정 절에서 모은다: "Codex가 ~했는데 ~라서 ~로 고쳤다/거부했다(시각·파일)".
5. **한계·안 만든 것·이유** — REQUIREMENTS에서 '안 만들 것'으로 둔 행(번호와 사유)과 PLAN 한계.
6. **깨지는 조건** — 입력 10배 · 동시 접속 · 외부 실패(파일 없음·DB 잠김·네트워크) · 시간대(UTC/KST)마다 한 줄: 어디서(파일·함수) → 어떻게 드러나나(증상·숫자) → 먼저 고칠 것.

그 뒤:
- **예상 문항 수 = 설명 카드 수**(최소 6 — 요구 8개를 다 만들었으면 8개) — 반드시 넣을 6개: 왜 그 방식으로 만들었나 / 입력이 늘면 어디서 먼저 깨지나 / 여러 사람이 동시에 접속하면 / 백엔드 구성과 코드 연결 / 프로덕션 배포 전 고려사항 / 핵심 동작과 확인한 방법. 나머지는 설명 카드마다 하나씩 이 과제 기록에서 고른다(예: AI 제안을 고친 부분, 가장 약한 입력, out/prove.md의 현행·기준안·우리 안·하한). 문항마다 "Qn. 질문" 1줄 + "답:" 1줄 — 4문장(사실 → 결정 → 근거 → 한계), 파일·함수 이름과 out/ 숫자를 넣는다.
- **AI_COLLABORATION 초안 A/B** — AI_COLLABORATION.md의 Q1~Q3 답 칸마다 초안 두 개를 `[초안A] …`·`[초안B] …` 두 줄로 직접 쓴다. A는 숫자 중심(out/ 숫자 · 테스트 n/n · 처리 전후 건수), B는 결정 중심(DECISIONS의 내 선택·이유 · 거부한 것). 둘 다 그 Q의 유도 문장(DOC_QUESTION_BANK 1장 — `[ ]`는 기록에서 채우고, 없으면 `[기록 없음]`)과 쓴 시그니처 슬롯(Dn) 1개 이상을 포함한다: Q1 "기준값과 딱 같은 경우는 [포함/제외]로 정했고 테스트 [이름]이 그 경계를 고정한다" / Q2 "Codex가 [무엇]을 넣으려 했으나 요구 [R/X번호]에 없어 되돌렸다(DECISIONS 거부한 것)" / Q3 "측정(규모·동시성·docker)은 D가 코드와 독립으로 돌려 out/에 남겼고, 소유 파일을 나눠 충돌 0". README 양식(질문 문장)은 바꾸지 않는다. "## 설명 준비"에는 초안을 다시 쓰지 않고 `### AI_COLLABORATION` 아래 한 줄만: "AI_COLLABORATION.md에 [초안] n곳".
- **초안 고르기** — 커밋 보고 끝에 "Q1-A Q2-B Q3-A처럼 답해라"를 쓰고 멈춘다. 사용자가 답하면 Q마다 고른 쪽만 남기고 다른 줄을 지운 뒤 `[초안A]`/`[초안B]` 표시를 지운다(문장은 고치지 않는다). LOG 본표에 `| S6 | $defend 초안 선택 Q1-A Q2-B Q3-A(사용자 답 그대로) | 초안 A/B 6개 | 내가 고른 것 3건 | 시각 |` 한 행을 쓰고 `[S 6/6] 초안 선택` 으로 AI_COLLABORATION.md · LOG.md만 커밋한다. 고르지 않으면 `[초안A]`/`[초안B]`가 남고 check_evidence가 WARN을 낸다.
- **읽기 카드** — out/defend_cards.md 맨 위, 아래 세 덩어리보다 먼저 `## 0. 읽기 카드` 6줄을 쓴다. 한 줄 = 한 틀, 값만, 문장 없이. 값은 아래 카드·숫자 표에서 가져오고 새로 계산하지 않는다. 없는 값은 `[기록 없음]` — 이 6줄이 곧 메울 것 목록이다.
  ```
  A 왜 그 방식 | 규칙: <한 줄 원리> | 기준: <담당자 기준값> | 테스트 n/n | 경계: 포함/제외 | 대안: <더 단순>/<더 정교> | prove: 현행 n·기준안 m·우리 안 k
  B 늘면      | 느린 곳: <파일:함수> | 1배 n ms → 10배 n ms | 입력 n = 사용 n + 버림 n(<사유>) | 먼저 바꿀 것: <하나>
  C 동시에    | 200 n · 409 n | 세션: <store/메모리>, 재시작 시 <남음/날아감>
  D 구조      | 입구→인증→검증→계산→저장→응답 | 없는 단계: <…> | 테스트 n/n
  E 배포      | 한 것: <…> | 안 한 것: <…> | docker: PASS/FAIL/SKIP | 먼저 할 것: <하나>(<파일>)
  F 확인      | 테스트 n/n | curl 200 n/n | 화면: <본 값> | 퀴즈 n회·틀림 n | 거부 1건: <무엇·왜>
  ```
- **답 카드 사본 out/defend_cards.md** — 읽기 카드 아래에 세 덩어리, 이 순서로:
  1. 맨 위 한 줄 **과제 계산 규칙**: PLAN '만들 것'의 ★1과 그 기능의 함수에서 뽑은 한 문장 + 그 파일·함수 이름(`규칙: … — 파일:함수`). D1·D6 카드의 `[규칙 한 문장]`·`[한 문장 규칙: …]`·`[계산 모듈 파일]`·`[함수]`는 이 줄에서 채운다.
  2. _playbook/DEFEND.md "1. 카드 6장"을 문장 그대로 복사하고 `[ ]` 칸만 코드·tests/·out/·DECISIONS에서 채운다. 문장은 고치지 않는다(사용자가 외운 문장이다). 채울 수 없는 칸은 `[기록 없음]`, DECISIONS에서 "해당 없음"인 슬롯은 카드째 "해당 없음 — README 범위 밖".
  3. 카드 아래에 DEFEND.md "3. 숫자 열 개" 표를 복사해 `값` 열을 더하고 각 행을 그 파일의 실제 값으로 채운다(없으면 `[기록 없음]`).
  DEFEND.md에 "1. 카드 6장" 절이 없으면 "답 카드 없음"이라고 보고하고 이 파일은 만들지 않는다.
- 장 4 "AI를 바로잡은 지점"이 비면 `기록 없음 — DECISIONS '거부한 것' 비어 있음`이라고 그대로 쓴다.

## 하지 않는 것
LOG의 다른 절·위 세 곳 밖의 파일 수정 / 사용자 답 전에 `[초안A]`/`[초안B]` 표시 빼기 / 근거 없는 문장 / 하지 않은 테스트·측정을 한 것처럼 쓰기 / 60줄 초과(넘치면 장마다 줄을 줄인다).

## 커밋
`[S 6/6] 설명 준비` 로 LOG.md · AI_COLLABORATION.md · out/defend_cards.md만 커밋하고 `git show --stat HEAD`를 붙인다. 역할 카드 C로 일하는 세션이면 커밋하지 말고 "커밋 준비됨: LOG.md(설명 준비 절) AI_COLLABORATION.md out/defend_cards.md"로 끝낸다. 초안을 고른 뒤에도 C 세션이면 LOG 본표를 쓰지 않고 "A에게 요청: LOG 본표 한 행 …" + "커밋 준비됨: AI_COLLABORATION.md"로 끝낸다.

## 끝 조건
LOG.md 끝 "## 설명 준비"가 6장 + 문항(설명 카드 수, 최소 6), 빈 줄 빼고 60줄 이내 · AI_COLLABORATION Q1~Q3에 `[초안A]`·`[초안B]` · out/defend_cards.md(답 카드가 있을 때) · "기록 없음" 개수가 보고에 있다.
