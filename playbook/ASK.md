# ASK — 담당자 질문·DM (개수 상한 없음 · 지목 조건은 숫자까지 · 수확률로 멈춘다)

**답이 섞이지 않게 한 메시지에 질문 하나. 순서가 우선순위다. 번호 붙여 몰아 보내지 않는다.**

**DM 1 — S1 15분, 입출력 한 건**
```
이 데이터에서 [항목 하나]를 넣으면 결과가 어떻게 나와야 하나요? 한 건만
```
**DM 2 — DM 1 답을 받은 뒤**
```
저는 '[입력]→[규칙]→[출력]'으로 이해했습니다. 맞나요?
```

> 담당자는 README가 "확인하라"고 지목한 곳의 숫자를 준다. 그 밖은 "아는 정보가 없어요"가 많다 — 그 주제는 두 번이면 닫고 README·데이터로 돌아간다.
> 보내고 **답을 기다리지 않는다.** 답이 오면 `기록만 해라: date로 시각, 아래 담당자 답 원문을 LOG '담당자 대화'에 —` 뒤에 붙인다.
> 담당자에게 할 일·기능 목록·기술(만드는 방법)을 묻지 않는다. 기술 용어(API·스키마·엔드포인트) 대신 담당자가 화면에서 보는 말로.

## 질문 운영 — 개수가 아니라 수확률로 멈춘다
- **개수 상한 없음.** 숨은 조건(몇 분 넘으면 안 쓰는지, 무엇을 먼저 줄이는지)은 물어야만 나온다. 줄일 것은 질문 수가 아니라 **답이 없는 질문**이다.
- **README가 "담당자에게 확인"이라고 지목한 조건은 숫자가 나올 때까지 판다.** 한 조건에서 숫자가 여러 개 나온다(상한 · 우선순위 · 요일·시간대 예외).
- **숫자를 제안해서 묻는다**: "몇 분까지 괜찮나요?"보다
  "15분 넘으면 안 쓰시는 편인가요, 10분인가요" — 고르거나 고쳐 준다.
- 답마다 LOG에 **새 정보 / 확인 / 모름** 태그. 한 주제에서 모름·"아까와 같아요"·"정하실 부분"이 **2번이면 그 주제를 닫고** PLAN '가정'에. **최근 3개 답이 모두 새 정보 없음이면** 질문을 멈추고 `$plan`.
- 남은 질문은 ② 중간 보고 DM에 붙인다 — 구현하다 생긴 질문이 더 날카롭다.
- S2 동안 C가 일하므로 질문 시간은 대기 비용이 아니다. 48분이 되면 남은 질문은 중간 보고로 넘기고 PLAN 확인 DM을 보낸다.

## 어떤 질문부터 — README 두께로 가른다
- **README 요구가 5개 이상**(REQUIREMENTS에 요구 행 ≥5): README 문장마다 「누가 · 몇 건 · 예외는?」. `$ask`가 **지목 조건 → 숫자 없는 행·모호한 말 → inventory 이상값** 순으로 골라 준다. 위에서부터 보낸다.
- **요구가 4개 이하**(README가 얇다): 장면 → 기준 → 숫자 순서.
  1. 가장 최근에 이 일을 하셨던 날, 처음부터 끝까지 어떻게 진행됐나요?
  2. 잘 된 것과 아쉬운 것을 어떻게 구분하세요?
  3. 가장 먼저 보시는 건요?
  4. 얼마나 자주, 한 번에 몇 건, 몇 명이 쓰나요?
  5. 틀리면 무엇이 얼마나 비싼가요?
  6. 빼야 하는 경우·예외·동률·취소는요?
  7. 기준값과 딱 같으면 통과인가요?
  8. 잘 됐다는 건 무엇을 보고 아실까요?
  9. 지금 값과 목표 값은요?
  10. 만약 ××는 없고 ○○만 된다면 업무에 쓸 만하실까요? (범위 축소 사전 동의 — 마지막)
- 데이터가 있으면 inventory 숫자를 그대로 넣는다: "같은 행이 n건 두 번 있습니다 / 처음 보는 코드 X가 n건 — 어떻게 처리할까요?"
- 답이 두 뜻이면(예: "오래된 건 빼" = 날짜인가 상태인가) 놓치면 비싼 쪽으로 잠정하고 "이렇게 처리해도 될까요?"로 한 번만 되묻는다.

## DM 5개 (5줄 이내 · 구조는 바꾸지 않는다 · 숫자가 하나 이상 들어간다)
**① 합의 확인 — S2 끝, PLAN을 보내며**
```
말씀해 주신 내용을 이렇게 정리했습니다.
1) ○○  2) △△
성공 기준은 {숫자}로 잡았습니다. 이번에는 ××는 빼고 위 두 가지를 확실히 되게 만들겠습니다.
이 방향이 맞을까요? 빠지면 안 되는 게 있으면 지금 말씀해 주세요.
```
**② 중간 보고 1 — 얇게 첫 기능이 끝까지 한 번 돈 직후(~75분)**
```
말씀해 주신 것 중 두 가지를 먼저 동작하게 만들었습니다.
1) ○○까지는 지금 바로 보실 수 있습니다.
2) 말씀하신 "△△" 표현을 그대로 기준으로 쓰고 있습니다.
남은 시간에는 ××를 다듬을 예정입니다. 지금 방향에서 바꾸고 싶은 게 있으실까요?
```
**②′ 중간 보고 2 — 깊게 1을 마친 S4 끝(~150분)**
```
요청하신 {n}가지가 모두 한 번씩 동작합니다. 핵심인 ○○는 {지표}로 재 보니 지금 {현행 값} → {우리 안 값}입니다.
남은 시간에는 확인과 정리만 하겠습니다. 이 숫자가 기대와 다르면 지금 말씀해 주세요.
```
**③ 결과 보고 + 수용 확인 — S5**
```
말씀해 주신 내용을 반영해서 이렇게 만들었습니다. 성공 기준{지표}: 지금 {현행 값} → {우리 안 값}(목표 {목표 값})입니다.
이 결과가 기대와 맞나요?
```
```
다르면 어디가요?
```
```
지금 상태로 업무에 쓸 수 있을지, 꼭 더 필요한 게 있는지 한 줄만 남겨 주실 수 있을까요? 못 하면 한계로 적어 두겠습니다.
```
**④ 거절 — 범위 추가 요청을 받았을 때**
```
좋은 의견 감사합니다. 그 부분은 지금 넣으면 ○○가 불안정해질 것 같습니다.
이번에는 빼고, 어떤 점이 필요하신지만 기록해 두겠습니다. 대신 지금 하고 있는 △△를 확실하게 마무리하겠습니다. 괜찮으실까요?
```
→ 보낸 직후 PLAN '안 만들 것'에 항목·이유. 메시지와 기록이 한 쌍.

## 답이 안 올 때
- 비워 두지 않는다. PLAN(또는 LOG)에 그대로:
```
> 결과 보고와 수용 확인을 요청했으나 응답을 받지 못함(대화 기록에 있음). 요청 내용: …
```
- 답을 기다리는 동안 추천대로 진행하고, PLAN '가정'에 잠정안을 적는다. 답이 오면 기록 → PLAN부터 고친다.
