## 0. 뼈대 파일 7개 — 이름과 한 줄 (가장 먼저 외운다)

| 파일 | 함수 | 하는 일 한 줄 |
|---|---|---|
| `server.js` | `createApp`, `start`, `readBody`, `send` | 진입점. 요청을 읽고(`readBody`, 1MB 넘으면 413·JSON 깨지면 400), 경로별로 보내고, 응답(`send`). `start`가 0.0.0.0·PORT(기본 3000)로 띄운다 |
| `src/auth.js` | `seed`, `login`, `who`, `setCookie` | 빈 저장소면 데모 계정 둘(operator / member)을 만들고, 로그인하면 세션 쿠키를 준다. 쿠키는 **HttpOnly·Path만** |
| `src/lock.js` | `exclusive(name, work)` | 쓰기 작업을 한 번에 하나. 같은 이름이 진행 중이면 기다리지 않고 **409** |
| `src/store.js` | `openStore` → (돌려주는 객체의) `get`·`set` | 영속 저장. `node:sqlite`가 있으면 SQLite, 없으면 같은 경로의 JSON. 기본 경로 `./var/app.db` |
| `src/time.js` | `fmt`, `parseLocal`, `minuteOfDay` | 업무 시각을 **Asia/Seoul**로만 읽고 쓴다. 시스템 시간대가 UTC여도 UTC 22:30 → KST 07:30 |
| `src/validate_schema.js` | `schemaKeys`, `compare` | 내보내기 JSON의 키를 **스키마 md 표에서 읽어** 대조. 빠진 키·남는 키를 돌려준다 |
| `Dockerfile` | — | 의존성 0이라 `npm install` 없음. `/app/var` 만들고 `chown` 뒤 `USER node`. HEALTHCHECK는 `/health` |

**요청 한 번의 경로(구조 한 장) — 이 문장을 통째로 외운다:**

> "요청이 들어오면 `server.js`의 `createApp`이 받습니다. 먼저 `auth.who`로 쿠키에서 누구인지 보고, 역할이 안 맞으면 403, 로그인이 없으면 401을 돌려줍니다. 그다음 `readBody`로 본문을 읽고, 입력을 검증한 뒤, 과제 계산은 `[계산 모듈 파일]`의 `[함수]`가 합니다. 쓰기 작업이면 `lock.exclusive`로 감싸서 동시에 두 번 오면 두 번째는 409입니다. 결과는 `store.set`으로 저장하고 `send`로 응답합니다. 내보내기는 `validate_schema.compare`로 키를 스키마 문서와 대조한 뒤 내보냅니다. 설정은 전부 환경변수에서 읽되 기본값이 있어 아무것도 안 줘도 뜹니다."

## 1. 카드 6장 — 4문장(사실 → 결정 → 근거 → 한계)

### D1. 단순 규칙 먼저, 정교한 대안은 한계로 (→ "왜 그 방식인가", "더 단순한/정교한 대안은")
- **사실** 과제는 `[기준: 예 — 상한 n분 안, 정원 n명]`이라는 조건만 주었고, 가장 좋은 답을 찾으라고는 하지 않았습니다.
- **결정** 그래서 `[계산 모듈 파일]`의 `[함수]`에서 `[한 문장 규칙: 예 — 조건을 만족하는 것 중 첫 번째를 고르는 탐욕 방식]`으로 정했습니다. 한 번 훑으면 끝나는 규칙입니다.
- **근거** 이 방식은 제가 네 문장으로 설명할 수 있고(4문장 퀴즈 `[n]`/4), 경계 테스트 `[테스트 이름]`에서 기준값과 딱 같은 경우가 `[포함/제외]`되는 것을 확인했습니다. 테스트 `[n]`개 중 `[n]`개 통과이고, `out/prove.md`에서 현행 `[n]` · 기준안 `[m]` · 우리 안 `[k]` · 이론 하한 `[h]`로 우리 안이 현행보다 `[차이]` 낫습니다.
- **한계** 대신 `[조건: 예 — 조건을 만족하는 후보가 여럿일 때]`는 최적이 아닐 수 있습니다. 더 정교한 방법(`[예 — 점수를 매겨 정렬]`)은 PLAN 한계에 대안으로 적었고, 그걸 안 한 이유는 설명 가능성과 시간입니다.

> 더 단순한 대안이 왜 부족했나 → "`[더 단순한 것: 예 — 무조건 첫 번째]`은 `[담당자가 말한 조건]`을 무시해서 `[누가]`가 잘못된 결과를 받습니다." / 더 정교한 대안을 왜 안 했나 → "설명 못 하는 코드는 제 것이 아니고, 시간 대비 점수가 안 나옵니다."

### D2. 쓰기 직렬화·읽기 스냅샷 (→ "여러 사람이 동시에 접속하면")
- **사실** 과제에는 운영자 여럿이 동시에 재계산이나 데이터 적용을 누르는 경우가 적혀 있지 않았습니다.
- **결정** `src/lock.js`의 `exclusive`로 쓰기 요청을 한 번에 하나만 처리하고, 진행 중에 같은 요청이 오면 기다리게 하지 않고 409로 거절합니다. 읽기는 마지막으로 저장된 결과만 보여 주므로 잠그지 않습니다.
- **근거** 같은 POST 2개를 동시에 보낸 테스트에서 200 하나·409 하나였고, 실제 서버에서도 `out/concurrency_check.txt`에 `[200 n·409 n]`으로 남겼습니다. 끝난 뒤에는 다시 200입니다.
- **한계** 이 잠금은 프로세스 하나 안에서만 듣습니다. 서버를 둘 이상 띄우면 잠금이 안 되므로, 그때 먼저 바꿀 곳은 `store`에 DB 수준 잠금(트랜잭션)을 넣는 것입니다. 세션도 `[store/메모리]`에 있어 `[재시작하면 남는다/날아간다]`.

### D3. 입력 = 사용 + 버림 검산 (→ "입력이 늘면 어디서 깨지나", "이상한 데이터가 오면")
- **사실** 제공 데이터에 `[완전 중복 n건, 빈칸 n건, -1 같은 표시값 n건]`이 있었고, 담당자가 `[HH:MM]`에 `[처리 방식]`이라고 답했습니다.
- **결정** 데이터를 빼거나 바꾸기 전에 `out/changes_log.md`에 전후 건수를 남기고, 계산 코드는 **입력 건수 = 사용 건수 + 버림 건수(사유별)**를 출력하도록 해서 이 등식을 테스트로 확인합니다.
- **근거** 처리 전 `[n]`건 → 후 `[n]`건이고, 그 처리로 결론이 `[바뀌었다/안 바뀌었다: 예 — 대상 n → m]`. 입력 10배에서는 `[함수]`가 `[n]`ms → `[n]`ms였습니다(`out/scale_check.txt`).
- **한계** 등식 검산은 같은 행이 두 번 들어간 완전 중복을 못 잡습니다. 그래서 중복은 inventory에서 따로 세어 처리 규칙을 정했습니다. 10배에서 가장 먼저 느려지는 곳은 `[함수]`이고, 이유는 `[예 — 모든 쌍을 비교해서 n²]`입니다. 먼저 바꿀 것은 `[예 — 미리 정렬·색인]`입니다.

### D4. 업무 시간대 고정·설정 기본값·의존성 0 (→ "프로덕션 배포 전 고려사항")
- **사실** 채점 환경은 제 환경과 다릅니다. 컨테이너 시간대는 UTC이고, `.env` 파일이 없을 수 있고, 네트워크가 막혀 있을 수 있습니다.
- **결정** 시각은 `src/time.js`가 Asia/Seoul로만 읽고 씁니다. 설정값은 전부 기본값이 있어(PORT 3000, DB_PATH ./var/app.db, 데모 비밀번호) 환경변수 없이도 뜹니다. 외부 패키지가 없어 Dockerfile에 `npm install`이 없고, `/app/var`를 만들어 `node` 사용자에게 준 뒤 `USER node`로 돌며 HEALTHCHECK는 `/health`입니다.
- **근거** 시각 테스트에서 UTC 22:30이 KST 07:30으로 나왔고, 스모크 테스트는 환경변수 없이 `/health` 200이었습니다. `docker build`와 `run` 뒤 `/health`는 `[PASS/FAIL/SKIP]`(`out/docker_build.txt`).
- **한계** 배포 요구 중 한 것: `[환경변수·헬스체크·Dockerfile·DB 영속 중 한 것]`. 안 한 것: `[예 — 로그 수집, HTTPS, 비밀값 관리, 백업]`. 먼저 할 것은 `[하나]`이고 바꿀 파일은 `[파일]`입니다.

### D5. 스키마 문서에서 키를 읽어 대조 (→ "내보내기·검증을 어떻게 보장하나")
- **사실** README가 내보내기 형식을 `[스키마 파일명]`으로 정했고, 채점에서 이 형식으로 검증한다고 했습니다. 키 이름이 한 글자만 달라도 0점이 될 수 있습니다.
- **결정** `src/validate_schema.js`의 `schemaKeys`가 스키마 md 표에서 키 목록을 읽고, `compare`가 내보낸 JSON과 대조해 빠진 키·남는 키를 돌려줍니다. 키 이름을 코드에 박지 않았습니다.
- **근거** 테스트에서 한 글자 다른 키가 빠진 키와 남는 키 둘 다로 잡혔고, 실제 내보내기 샘플 `[out/파일]`은 `[ok / missing n·extra n]`이었습니다.
- **한계** 키 이름만 봅니다. 값의 타입이나 범위(숫자인지, 음수인지)는 안 봅니다. 그게 다음에 넣을 검사이고, 넣을 곳은 `compare` 바로 뒤입니다.

### D6. 진입점 → 인증 → 검증 → 계산 → 저장 → 응답 (→ "백엔드 구성과 코드가 어떻게 연결되나")
- **사실** 요구가 `[n]`개라 파일을 역할별로 나눴고, 외부 프레임워크 없이 Node 내장 http만 썼습니다.
- **결정** 0장의 "구조 한 장" 문장을 그대로 말한다.
- **근거** 스모크 테스트가 뜨는 것·0.0.0.0·`/health`를, `feat_auth`가 401·403 경계를, `[과제 테스트]`가 계산을 확인합니다. 테스트 `[n]`개 중 `[n]`개 통과입니다.
- **한계** 없는 단계를 솔직하게: `[예 — 입력 검증은 필수 칸 존재만 본다 / 결과 검증 단계가 없다 / 잠금은 프로세스 안]`. "없다, 그래서 `[결과]`"로 말한다.

## 4. 쓰지 않는 말 → 대신 쓰는 말

| 쓰지 않는다 | 대신 |
|---|---|
| "테스트했습니다" | "테스트 `[n]`개 중 `[n]`개 통과, `out/test_result.txt`에 있습니다" |
| "더 확인이 필요합니다" | "확인하려면 `[파일·명령]`을 보면 됩니다. 저는 `[무엇]`까지 봤습니다" |
| "AI가 그렇게 만들어서" | "제가 `[무엇]`을 그렇게 두기로 했습니다. 이유는 `[…]`" |
| "제가 직접 썼습니다"(DECISIONS·AI_COLLABORATION·4문장) | "Codex가 후보를 내고 제가 `[번호]`로 골랐습니다. 고른 이유는 `[…]`, 근거는 `[out 파일]`입니다" |
| "시간이 없어서" | "`[R번호]`는 안 만들 것으로 두었고 사유는 `[…]`입니다. 만든 것은 끝까지 확인했습니다" |
| "잘 돌아갑니다" | "`[경로]`가 200이고 화면에서 `[값]`을 봤습니다" |
| 모르는 걸 아는 척 | "그건 확인하지 않았습니다. 확인하려면 `[A]`를 보면 됩니다" |

## 4문장 골격 (40초)
```
사실  "문제에는 X라고만 쓰여 있었습니다."
결정  "그래서 Y로 정했습니다."            ← 파일·함수 이름
근거  "Z 때문입니다."                     ← 점수 (숫자 2~3개)
한계  "대신 W인 경우엔 틀립니다."          ← 신뢰
```
- 질문의 전제가 내 구현과 다르면 차이를 먼저 밝힌다: "질문의 전제 …는 제 구현과 다릅니다, 실제로는 …".
- 3분쯤 핵심을 먼저 적고 나머지를 보강한다. "더 확인해야 합니다"로 끝내지 않는다 — "확인하려면 A(파일·명령)를 보면 됩니다".

## 세 가지 금지
| 금지 | 대신 |
|---|---|
| 모르는 걸 아는 척 | "그건 확인하지 않았습니다. 확인하려면 A를 보면 됩니다." |
| 근거 없는 "테스트했습니다" | "테스트 n개 중 n개 통과, out/test_result.txt에 있습니다." |
| AI 탓·시간 탓 | "제가 X를 안 만들 것으로 뒀습니다. 이유는 Y입니다." |

## 제출 확정 뒤 대기 5~10분
1. "설명 준비" ①③⑥을 한 번 더 읽는다.
2. 위 6유형을 하나씩 소리 내어 4문장으로 답한다. 막히면 그건 기록에 없는 것이다 → 서술형에서 정직하게 연다.
